# 断点续跑：判定表怎么写

每个项目写一张“已有文件 → 接到哪一步”的表，放在 `跑法.md` 或项目指令里。新对话按表接，不靠记忆。

## 写法

- 左列只写**能用文件判断的条件**：文件在不在、登记表里某个状态、记录末尾有没有某一行。
- 右列写**接到哪一步**，要停的写“停 ①”这样的停点名。
- 几行同时命中，取**最靠下**的一行（进度最远）。所以按流程顺序从上往下排。
- “人已同意”不能从文件判断时，写成“停 ×；人已表示同意则进下一步”，并且只认人的原话。

## 例子（虚构项目《雾港来信》，见 folder-layouts.md）

| 已有文件 | 接到 |
|---|---|
| 只有 `N_原稿.md` | 第 1 步：写脚本 |
| `N_脚本.md` + `N_脚本说明.md`，没有素材需求 | 停 ①：人看脚本说明；人已同意则进第 2 步 |
| `N_素材需求.md`，`素材图/` 不全或登记表还有“待生成” | 第 2 步，只补缺的图 |
| 登记表有“已生成”但没“已批准” | 停 ②：人看图 |
| 本集素材都“已批准” | 第 3 步：镜头表 |
| `N_镜头表.md`，没有视频 | 停 ③；人已同意且复核放行则进第 4 步 |
| 视频已有，`N_生成记录.md` 末尾没有“本集完成”行 | 停 ④：人看片；都看完也要问“这一集还有要调整的吗” |
| `N_生成记录.md` 末尾有 `本集完成：负责人确认（日期）` | 更新已定设定表、进度摘要，做规则进化，再开下一集 |

## 常见坑

- **用“对话里说过”判断进度**：换了对话就错。只看文件。
- **把备份文件当进度**：`旧版_3_脚本.md` 不算 `3_脚本.md`。
- **“本集完成”由 AI 自己写**：这一行只在人明确说“这一集没有要调整的了”之后写，写上日期。
- **上游改了下游不知道**：改了脚本，镜头表就过期了；复核记录里带文件哈希，哈希对不上自动失效。
