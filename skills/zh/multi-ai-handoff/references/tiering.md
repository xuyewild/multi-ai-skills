# 按难度选模型

目的：把订阅额度花在真正难的地方。高档模型用在设计，低档模型做整理和核对。

## 打分

每个能单独验收的工作单元打一次分：

| 项 | 范围 | 看什么 |
|---|---|---|
| N 原创性 | 0–4 | 0 照抄整理；4 从零设计核心内容 |
| K 条件耦合 | 0–4 | 要同时满足的规则、上下游约束有多少 |
| A 不确定性 | 0–3 | 需求、事实、平台行为有多少不清楚 |
| F 返工代价 | 0–3 | 错了要浪费多少钱和时间，会不会连累下游 |
| E 方案清晰度 | 0–3 | 有没有现成方案、模板、例子 |

`S = 2N + 2K + A + F − 2E`

## 派档（Claude Code 子 agent 为例）

| S | 档位 | 模型 · 思考 | 典型活 |
|---|---|---|---|
| — | 脚本 | 不用模型 | 哈希、格式校验、文件比对 |
| ≤ 1 | tier-light | Haiku · low | 提取清单、去重、词表扫描、复核前的机械核对 |
| 2–7 | tier-standard | Sonnet · medium | 常规写作、普通编译 |
| 8–12 | tier-complex | Sonnet · high | 方案已定、条件很多的编译 |
| 13–17 | tier-design | Opus · medium | 核心剧情、人物、关键镜头设计 |
| ≥ 18 | tier-deep | Opus · high（可到 xhigh/max） | 已定位的重大疑难 |

`templates/tier-agents/` 里有这五个子 agent 的定义文件，放进项目的 `.claude/agents/` 就能用。

## 几条经验

- **核心创作直接给高档**，不必先让低档失败一次。
- **方案已定、编译复杂的给 tier-complex**，不要再找 Opus 重新设计一遍。
- **工具问题不升档**：文件缺失、路径错、权限、平台报错、生成随机偏差，先查原因。
- **长不等于难**：大量简单内容切块交低档。
- **同一问题最多一次有实质变化的定向修改**，还不过就重新判断原因或换档，不盲目重跑。推理返工和付费生成重试分开计。
- **用 xhigh / max 前先写清楚**：难题是什么、排除了哪些非推理原因、为什么值得、完成条件。同一时间最多一个这样的单元。

## 记录与核实

每次委派留一行：`单元｜S｜档位｜理由`。

模型自己说“我是 Opus”不算证据，以界面显示为准；看不到就写“未核实”。

以下环境变量会把所有子 agent 悄悄统一成同一个模型，用分档时都不要设：`CLAUDE_CODE_SUBAGENT_MODEL`、`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`、`CLAUDE_CODE_EFFORT_LEVEL`。
