# 付费动作：先问、先记账、只点一次

适用于视频生成、图像生成、付费 API、去噪重绘等每次都扣钱或积分的动作。

## 项目开头确认一次

模型、画幅、分辨率、预算单位和总额、单个单元的重试上限、并发数、要不要先出低清样片。只问缺的项，写进生成记录开头，然后建账本：

```bash
python3 ledger.py 00_项目/成本账本.json init --unit 积分 --limit 20000 --retry-limit 3
```

费用估算按“时长 × 分辨率”分档，用项目开头实测的单价算。设置一变（换模型、换分辨率）就重新确认，不偷偷降规格。

## 每次提交

```bash
python3 ledger.py 账本.json reserve --id ep3-n07-a1 --item ep3/n07 --cost 120   # 预留
# …在平台上只点一次生成…
python3 ledger.py 账本.json submitted --id ep3-n07-a1 --task <平台任务号>
python3 ledger.py 账本.json settle --id ep3-n07-a1 --charge 118                 # 按实际扣费结算
```

- 点了生成但页面没反应、不知道受理没有：`unknown`。之后这个单元任何新的预留都会被拒，**先去平台对账**，确认没受理再继续。这一条挡掉了实战里最贵的错误：重复点击。
- 平台失败退款：`refund`，重复退款只记一次。

## 重试分类

| kind | 什么时候 | 占上限吗 |
|---|---|---|
| first | 第一次 | 占 |
| retry | 平台报错、没出片的补跑 | 占 |
| autofix | AI 判为硬伤后自动修一次 | 占 |
| human | 负责人看完点名重做 | 不占，单独计 |

## AI 粗看怎么写

出片后 AI 先看，但只是帮人缩小范围：

- 按镜头抽帧，做成联系表；逐题答“是／否／拿不准”，写证据的秒数。
- 写清：查了几题、疑点在哪、最弱的三处。
- 不写“粗看通过”。动作、口型、声音这些要看动态、听声音的，写“留给人看”。
- 人看片后发现、AI 漏掉的，记进项目的“看片必查”清单，下次 AI 先查这些。

## 硬伤自动修

只修明确硬伤：人物缺失、串脸、比例崩坏、主体不对。只出字幕的不算。

1. 先排除执行问题（图传错、参数错、提示词没粘全）。
2. 定位到镜头和秒数。
3. 判断原因：写法问题就改提示词，随机问题就重抽。
4. 能只补出错的那一段就补一段，切不开才整段重做；替换写进剪辑备注。
5. 原因判断不出、要动剧情台词、拿不准补一段还是整段，就问人。

## 不做

- 不为了验证某条规则单独多花钱生成测试片段。
- 不因为新模型失败就自己换旧模型。
- 不回头改已经采用的产物。
