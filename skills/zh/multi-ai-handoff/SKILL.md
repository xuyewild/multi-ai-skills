# 多 AI 分工与交接

这套做法来自半年 AI 漫剧生产：一个导演，加上 Claude、Codex 和若干子 agent，前后几千条片子，每天几十次付费视频生成。核心只有一句：**AI 之间只认文件，不认对话；每一次交接都要有人检查，花钱和拍板的事只归人。**

## 1. 三个角色

每个任务先写清这三个角色，可以是同一个模型的不同会话，但不能是同一个上下文。

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **执行者** | 产出文件、跑脚本、操作浏览器、提交生成 | 不给自己的产物下“通过” |
| **检查者** | 对照要求看真实产物，给有证据的结论 | 不改产物、不批准、不花钱 |
| **负责人（人）** | 批准关键产物、花钱、定方向、合并规则改动 | — |

实战中的分工例子（按工具长处分，不按“哪个模型更聪明”分）：

| 工作 | 执行 | 检查 |
|---|---|---|
| 剧本丰富、分镜写作 | Claude | 独立复核子 agent |
| 生成资产图、操作生成平台 | Codex（内置生图、浏览器） | Claude |
| 生成后的粗看 | Codex 跑抽帧和音频脚本 | Claude 看联系表逐题答 |
| 最终采用 | — | 负责人看片 |

一个工具不可用时，另一个可以兼任执行，但检查照做，交付里写明“这次执行和检查没有分开”。

## 2. 交接只认文件

- 每一步的输入、输出都是**固定文件名**（例如 `第3集/3_分镜.md`）。下一步开工先看文件在不在，缺了就停下报“哪一步、缺什么文件”，不替上游补。
- 对话里说“已完成”“已确认”不算数，以文件为准。进度 = 文件夹里有什么。
- 交接包写法见 [templates/handoff-package.md](templates/handoff-package.md)：**给路径，不给结论**。不写“已通过”“应该没问题”，不只给作者自己的总结。
- 派活给另一个 AI 时，第一句让它先加载对应 skill 和项目规则文件，冲突以规则文件为准。

项目文件夹怎么组织、规则怎么记，见配套 skill `project-memory`。

## 3. 交接前独立复核

执行者自检和脚本校验之后、交给下一步之前，另开一个**独立上下文**的检查者复核。

1. **复核者只读**：只给 Read、Glob、Grep（Claude Code 子 agent 定义见 [templates/independent-reviewer.md](templates/independent-reviewer.md)）。不在制作会话里自审，不用 fork（fork 会继承作者的思路）。
2. **任务包**：要求原话和出处、待审文件路径、必读的上下游文件、适用规则、工具报告（标明是工具报告）、范围和完成条件。
3. **结论只有四种**：`PASS`、`REVISE`（列问题，交原执行者改）、`NEEDS_EVIDENCE`（缺证据，主控补了再派）、`NEEDS_DECISION`（规则冲突或要人定）。每条问题要有位置、依据、看到的事实、影响、怎么改、谁来改。
4. **长清单逐项查**：容易漏的阶段给一张编号检查表，复核报告每个编号一行、带证据（行号、节点号、看到的事实）。“已检查”“符合要求”不算证据。
5. **用脚本记账放行**：`scripts/review_gate.py record` 把复核报告和所审文件的 SHA256 记下；下一步开工前 `check`，文件变了就自动失效（STALE），要重新复核。用法见 [references/review-gate.md](references/review-gate.md)。
6. **返工有上限**：首次之外最多自动返工两轮；同一处连续 3 轮不过，或连续两轮没改善，停下交负责人。不降标准、不伪造通过、不无限重跑。
7. **复核者看不到的不下结论**：只拿到静帧就不判动作连贯、口型、声音，写“证据不足，留给人看”。
8. **PASS 不等于批准**：复核只说明这一版、这个范围查过了；批准仍归负责人。

PASS 之后又小改，只做**增量复核**（只审改动段和牵连项）；但进入付费生成前，对现行版本整份复核一次。

## 4. 按难度选模型

拆成能单独验收的小单元，每个单元打分再派档，不要为一个难点把整个项目长期升到最高档。

`S = 2N + 2K + A + F − 2E`
N 原创性 0–4｜K 条件耦合 0–4｜A 不确定性 0–3｜F 出错返工代价 0–3｜E 已有方案清晰度 0–3

| S | 档位（以 Claude 为例） |
|---|---|
| 有可靠脚本能做 | 直接跑脚本，不用模型 |
| ≤ 1 | 轻量（Haiku · low）：提取、整理、格式检查、哈希和词表核对 |
| 2–7 | 标准（Sonnet · medium） |
| 8–12 | 复杂编译（Sonnet · high）：方案已定、条件很多 |
| 13–17 | 设计（Opus · medium）：核心剧情、关键镜头 |
| ≥ 18 | 深度（Opus · high 及以上），先写清难点和完成条件 |

- 文件缺失、路径错、平台报错、生成随机偏差：先查原因，不升档。
- 输入长不等于难；设计定稿后，编译和整理回落低档。
- 每次委派留一行：`单元｜S｜档位｜理由`。实际用了哪个模型以界面为准，模型自述不算证据。

细则和分档 agent 定义见 [references/tiering.md](references/tiering.md)。

## 5. 付费动作

生成视频、出图、调用付费 API 都是付费动作，规则比普通任务严：

1. **先问再跑**：第一次提交前把数量、模型、预计费用、重试上限列给负责人，说“跑”才开始。负责人可以在项目规则里授权“核对后直接生成”，授权写进规则台账才算。
2. **先记账再点**：`scripts/ledger.py reserve` 预留 → 只点一次 → 记任务号 → 按实际扣费 `settle`。点了却不知道是否受理，记 `unknown`，**先对账，不重按**。
3. **重试有上限**：每个单元首次 + 报错补跑 + 自动修合计不超过上限（实战用 3 次），超过交负责人。人点名的重做单独计。
4. **硬伤自动修一次**：只限明确硬伤（人物缺失、串人、比例崩坏、主体不对）；先找原因（写法问题改提示词，随机问题重抽），能只补出错的一段就不整段重做。
5. **AI 粗看 ≠ 采用**：AI 列疑点和最弱三处，不写“粗看通过”；采用由人定。
6. **不验证就不说已确认**：没实际看过、听过的效果，不能说成确认过。也不为了验证规则单独花钱生成测试片段。

记账格式和命令见 [references/paid-actions.md](references/paid-actions.md)。

## 6. 只归人的事

AI 不做，也不代答：批准关键产物（资产图、成片）；超预算或未授权的花钱、充值；核心方向、人物关系、结局、风格基调；改人锁定或亲手改过的内容；合并规则或 skill 改动到正式分支；删文件；改全局设置或别的项目。

AI 不写“负责人已确认 / 已批准 / 已看过”。拿不准一件事归谁，就当它归人。

## 7. 问人的方式

- 只在**停点**问：定好每个阶段停在哪（例如：方案、关键素材、提示词、成片），停点只给文件名和一句说明。
- 要人拿主意的，一次问清、最多四个，每个给字母选项，推荐项放第一个，人回“1A 2C”就够。格式见 [templates/decision-card.md](templates/decision-card.md)。
- 能从规则、记录、常规做法定的不问，在交付开头用一句话写明假设。
- 人的纠正当场改完，再按类写回项目文件（见 `project-memory`），下次自动带上。

## 8. 失败只报两件事

哪一步、缺什么。不替别的环节修，不写长诊断报告。
